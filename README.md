# GameHub

REST API для профилей игроков, рейтинга, достижений и уведомлений. Python 3.12, FastAPI, redis-py, Redis 7.4. Все данные хранятся в Redis.

## Запуск

Из каталога с `docker-compose.yml`:

```bash
docker compose up -d --build --wait
docker compose ps
curl http://localhost:8000/health
```

## Архитектура

| Сервис | Порт на хосте | Назначение |
|---|---:|---|
| `app` | 8000 | REST API |
| `worker` | нет | Потребитель уведомлений |
| `redis-master` | 6379 | Начальный мастер |
| `redis-replica-1`, `redis-replica-2` | 6380, 6381 | Две начальные реплики |
| `sentinel-1`, `sentinel-2`, `sentinel-3` | 26379, 26380, 26381 | Обнаружение мастера и автоматическое переключение, кворум 2 |

Приложение получает мастер и реплики через Sentinel. Записи и чтение профиля идут на мастер, чтение рейтинга и достижений на реплики. Репликация асинхронная, поэтому сразу после записи реплика может вернуть предыдущее значение.

При запуске приложение проверяет соединение. В [app/redis_client.py](app/redis_client.py) настроены таймауты, ожидание мастера при старте и повторные попытки чтения. Записи автоматически не повторяются, чтобы при потере ответа не увеличить счётчик дважды.

В [config/redis.conf](config/redis.conf) включены RDB, AOF с `appendfsync everysec` и переписыванием при росте на 100%. Лимит памяти 256 МБ, политика вытеснения `volatile-lru`. Запись разрешена при наличии хотя бы одной реплики с лагом до 10 секунд. Реплики принимают только чтение.

В [config/sentinel.conf](config/sentinel.conf) заданы кворум 2, `down-after-milliseconds 5000` и `failover-timeout 15000`. После переключения мастером может стать любой Redis-контейнер. Compose копирует конфигурации в тома при первом запуске, чтобы Redis и Sentinel могли сохранять текущие роли при перезапуске.

## Данные

| Ключ                | Тип        | Содержимое                                  | Срок хранения                |
|---------------------|------------|---------------------------------------------|------------------------------|
| `player:{id}`       | Hash       | `name`, `level`, `region`, `created_at`     | Без TTL                      |
| `logins:{id}`       | String     | Число входов                                | 86400 секунд с первого входа |
| `cache:player:{id}` | String     | JSON профиля                                | 60 секунд                    |
| `tournament:main`   | Sorted Set | ID игроков и очки                           | Без TTL                      |
| `achievements:{id}` | Set        | Названия достижений                         | Без TTL                      |
| `notifications`     | Stream     | `player_id`, `type`, `message`, `timestamp` | Сообщения за 7 дней          |

При чтении профиля сначала проверяется кеш. При промахе профиль читается из Hash и кешируется на 60 секунд. Изменение профиля удаляет кеш и добавляет уведомление. `WATCH` предотвращает запись устаревшего профиля в кеш при одновременном обновлении.


## API

Тело запроса передаётся в JSON. Успешные запросы возвращают HTTP 200.

| Метод | Путь                                           | Действие                                                        |
|-------|------------------------------------------------|-----------------------------------------------------------------|
| GET   | `/health`                                      | Доступность мастера и число подключённых реплик                 |
| POST  | `/api/players/{id}`                            | Создать или обновить профиль; `created_at` сохраняется          |
| GET   | `/api/players/{id}`                            | Получить профиль; заголовок `X-Cache` содержит `MISS` или `HIT` |
| PATCH | `/api/players/{id}/level`                      | Изменить уровень на `delta` через `HINCRBY`                     |
| POST  | `/api/players/{id}/login`                      | Увеличить счётчик входов, вернуть `count` и `ttl`               |
| POST  | `/api/leaderboard/score`                       | Прибавить `score` игроку `player_id` через `ZINCRBY`            |
| GET   | `/api/leaderboard/top?limit=10`                | Получить топ по убыванию очков                                  |
| GET   | `/api/leaderboard/rank/{id}`                   | Получить место игрока и результат `ZRANK`                       |
| POST  | `/api/players/{id}/achievements`               | Добавить достижение `name` через `SADD`                         |
| GET   | `/api/players/{id}/achievements/{name}`        | Проверить достижение через `SISMEMBER`                          |
| GET   | `/api/players/{id1}/achievements/common/{id2}` | Получить пересечение через `SINTER`                             |
| POST  | `/api/players/batch`                           | Загрузить массив `players` через pipeline                       |

`rank` начинается с 1 по убыванию очков. `redis_rank` содержит результат `ZRANK`: индекс с 0 по возрастанию очков. Повторное добавление достижения возвращает `added: false`.

Ошибки: 404 для отсутствующего игрока, 422 для некорректных данных, 409 при повторяющемся конфликте одновременных обновлений, 503 при недоступности Redis или отказе записи из-за отсутствия реплик. `/health` проверяет соединение и может отвечать 200, когда запись уже запрещена.
